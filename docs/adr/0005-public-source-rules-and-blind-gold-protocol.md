# ADR-0005: Public-source rule text with element tags, and a blind, frozen gold protocol

- Status: accepted
- Date: 2026-09-04
- Scope: `src/caregap/measures/rules/json/*.json`, `src/caregap/measures/rule_text.py`, `src/caregap/measures/value_sets/`, `scripts/sync_rule_text.py`, `scripts/scan_codes.py`, `scripts/gold.py`, `scripts/freeze_gold.py`, `src/caregap/evals/gold.py`, `evals/gold/`
- Related: `docs/SPEC.md` sections 2, 6 and 12; ADR-0001; ADR-0002; ADR-0004; `evals/README.md`

## Context

Two things must be true of a public portfolio repository that claims HEDIS alignment: it must
not reproduce licensed NCQA specifications, and its headline numbers must be measured against
labels that were not produced by the thing being measured. Both are easy to get wrong quietly.

NCQA's HEDIS technical specifications and value sets are licensed. What is public is the CMS
Star Ratings Technical Notes (US-government public domain), NCQA's own one-paragraph measure
summaries and the eCQI pages (readable, citable, not to be quoted at length), and the ACC/AHA
cholesterol guideline's statin-intensity table. Synthea, the only data source (no MIMIC or other
real or de-identified data anywhere), represents some public criteria well, some partially, and
some not at all.

The labeling problem is harder. This is a solo project: there is no clinical abstraction team.
Labels written by the engine's author after reading engine output are circular; labels written
by a model that also powers the validator are suspect unless the model is isolated from the
engine and the rules it applies are written down first.

## Decision

### Rule text: every element tagged and cited

`src/caregap/measures/rules/json/<measure>.json` is generated by `scripts/sync_rule_text.py`
from the sibling `hedis-spec-copilot` (P2) committed corpus of the CMS 2026 Part C & D Star
Ratings Technical Notes. Every rule element carries one of three tags:

- `quoted`: a verbatim sentence from the Technical Notes with a page citation; the script
  asserts each quoted sentence is a substring of the cited section and fails when the corpus
  changes;
- `demo_choice`: a parameter this demo fixed (window anchoring, evidence definitions, product
  choices such as "SPD excludes the SPC denominator"), with the reason and a citation to
  `docs/SPEC.md` section 2 or to a cite-only public page;
- `not_representable`: a public criterion Synthea or P6 cannot evidence (palliative care, I-SNP
  enrollment, frailty claims, bilateral mastectomy, total colectomy, cirrhosis, myopathy, IVF,
  clomiphene), listed so the coverage table and the UI show what the engine does not compute.

NCQA, eCQI and ACC/AHA sources are recorded as `public_web_cite_only`: nothing is quoted from
them beyond a title. `docs/MEASURES.md` is rendered from the same JSON
(`--render-docs`), `GET /v1/measures` serves it, and the validator's evidence packet lists the
element ids so a verdict cites a rule element, not a paraphrase. Each measure's coverage table
labels every public exclusion criterion `observable | partial | not_representable`.

Value sets follow the same discipline (`src/caregap/measures/value_sets.py`): sources are
allowlisted (`p6-valuesets-2026.08` only through `p6_vendored.json`, `synthea-scan`,
`public-acc-aha`, `public-cms`); every code in a P1 set must appear in the committed 237-bundle
scan `value_sets/SCAN.md` (`scripts/scan_codes.py`) or be flagged `untested_by_data` with a
note; `statin_intensity.json` is cross-checked against an independent dose-band reading of the
ACC/AHA table (`tests/unit/measures/test_value_sets.py`).

### Gold protocol: blind, value-set-agnostic, frozen before engine contact

The unit of evaluation is `(patient, measure)` at one `as_of` (`2025-12-31`, a complete
MY2025). Gold labels are `not_eligible | closed | excluded | open | escalate`.

1. **Rules first.** The rule JSON and a written labeling guide (`evals/gold/LABELING_GUIDE.md`)
   exist before any patient is selected. The guide restates the demo-grade rules in the words a
   labeler applies: windows, age at December 31, what counts as a BP panel, the on-therapy
   definition of ADR-0002, the E1-E7 conditions that make a unit `escalate`.
2. **Selection on descriptive facts.** Patients are chosen from a stratified Synthea panel by
   descriptive facts (age band, sex, diagnosis presence, encounter counts), never by an engine
   verdict, targeting at least eight eligible members per measure, at least twelve no-gap probes,
   and at least six escalation carriers.
3. **Snapshots.** `scripts/gold.py snapshot` writes the raw P6 record for each selected patient
   with every section and every observation code (no `observation_codes` filter in
   `caregap.p6.client.ENGINE_SECTIONS`): the labeler sees everything, not a projection chosen
   by the engine's value sets.
4. **Value-set-agnostic worksheets.** A worksheet per patient lists the events (codes, displays,
   dates, statuses) without importing any value set or rule module, so a labeler cannot inherit
   the engine's code membership decisions; events that a labeler judges to match a concept but
   that fall outside the listed codes are reported and collected in `evals/gold/CODE_AUDIT.md`.
5. **Blind LLM labelers.** Labels are produced by a blind LLM labeler (Claude, run as Claude
   Code agents) that receives only the labeling guide and one worksheet at a time, has no access
   to the engine, its verdicts, its value sets or this repository's source, and returns per
   measure a status, a rationale, the decisive dates, an `uncertain` flag and any
   events-outside-listed-codes. A second, independent labeler (B) labels a 12-patient subset the
   same way. The labeler id is recorded on every row (`llm-blind-claude-v1-A` / `-B` by default
   in `scripts/freeze_gold.py`). No label in the gold set was written by a human.
6. **Split by hash.** `split = "dev" if int(sha256(patient_id)[:8], 16) % 3 == 0 else "test"`
   (`caregap.evals.gold.expected_split`, mirrored in `scripts/freeze_gold.py::split_for`). The
   loader refuses any row whose stored split disagrees with the hash, so an item cannot be moved
   by hand into or out of the published test column.
7. **Freeze before engine contact.** `scripts/freeze_gold.py` writes `evals/gold/gap_cases.jsonl`
   (labeler A), `second_labeler.jsonl` (B), `AGREEMENT.md` (A vs B, exact and collapsed
   gap / no_gap / escalate agreement, per measure, with every disagreement listed),
   `CODE_AUDIT.md`, and `FREEZE.json` carrying the sha256 of `gap_cases.jsonl`, the counts per
   split and measure, the git sha, and `engine_contact_before_freeze: false`. It refuses to
   overwrite an existing freeze without `--force`. The pipeline and outreach tiers refuse to run
   when the file no longer hashes to the frozen value
   (`caregap.evalrun._require_frozen`; `caregap.evals.gold.freeze_status`).
8. **Adjudication on the dev split only.** After engine contact, disagreements on dev items may
   be adjudicated and recorded in `evals/gold/ADJUDICATION.md` with the count of changed labels
   published; test-split labels are never edited after the freeze.
9. **Agreement and spot-check.** The A-vs-B agreement on the 12-patient subset is published in
   `AGREEMENT.md`. A human spot-check of those items is **pending**; until it exists, the
   artifact and the README say so rather than implying human verification.

### Honesty statement and publication rules

The README carries, verbatim, the statement from `docs/SPEC.md` section 6: the headline
precision/recall measures the deterministic engine (plus code-verified validator decisions)
against demo-grade rules applied by a blind labeler (an LLM working from worksheets, independent of the engine; human spot-check pending); it is independent of the drafting agent; agents are
measured separately. "Hand-applied" means applied from the written rules by a labeler who never
saw the engine; that labeler is a model, not a person, and `evals/README.md` says so.
Per-measure rows publish only when the test split holds at least five gold-open units (three
for BCS, where mammography is rare in Synthea); otherwise the row is `insufficient` and the
headline carries the caveat. TSC and SNS are reported as counts, never as ratios.

## Consequences

### Positive

- No licensed text is reproduced; every quoted sentence is traceable to a public-domain page,
  every demo parameter is labelled as such, and every criterion the engine cannot see is listed
  rather than silently dropped.
- The labels were fixed, hashed and split before the engine saw them; a reviewer can verify the
  freeze hash, the split rule and the absence of edits to test labels from the committed files.
- Worksheets that carry no value sets separate two questions that are usually conflated:
  "is this code in the right set" (audited in `CODE_AUDIT.md`) and "was the rule applied
  correctly" (the headline).
- Two independent blind labelers give a measured, published agreement rate instead of an
  assumed one.

### Negative

- The labels are model-produced. A blind LLM applying a written rule is not a clinician
  abstracting a chart; systematic misreadings shared by both labelers would not show up in the
  A-vs-B agreement. The human spot-check that would bound this is pending.
- The headline measures fidelity to the written demo rules, which are themselves approximations
  of public summaries of licensed specifications. It says nothing about NCQA-certified rates and
  little about clinical truth (for example, the ADR-0002 status leak affects gold and engine
  identically).
- A hash-derived split does not control per-measure counts; some measures may fall under the
  publication guard and stay `insufficient` until the panel grows.
- Synthea prevalence quirks (rare mammography, frequent prior-hospice codes, statins authored
  once) shape both the label distribution and the engine's error profile; raw counts are
  published beside every ratio for that reason.
- Selection on descriptive facts by the engine's author is not selection by an outsider; the
  protocol limits what the author can see (no verdicts) but not what the author knows about the
  rules.

## Alternatives considered

1. **Human labeling.** Not available for a solo project at this scale and timeline. The protocol
   keeps the human where one is affordable: a 12-item spot-check of the labelers' work and of the
   outreach judge, both reported as pending until done.
2. **Labels derived from engine output, then corrected by hand.** Rejected. It is circular:
   every engine error the corrector misses becomes a "correct" label, and the corrector has seen
   the answer sheet.
3. **Quoting NCQA specifications.** Rejected: licensed text. The Technical Notes are public
   domain and carry the measure descriptions, exclusions and time frames that the rules need;
   everything finer is a tagged demo choice.
4. **No freeze, labels editable as the engine improves.** Rejected. It turns the test split into
   a second dev split and makes every published number unfalsifiable.
5. **A single labeler with a later self-agreement re-label** (the SPEC section 6 wording).
   Superseded by a second independent labeler on the subset; the self-agreement variant is a
   weaker check because the same context repeats.
